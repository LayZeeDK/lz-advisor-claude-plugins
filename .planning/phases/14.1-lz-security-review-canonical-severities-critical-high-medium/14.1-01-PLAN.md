<objective>
Migrate the `lz-security-review` skill + `security-reviewer` agent output contract from the
`Critical / Important / Suggestions / Questions` taxonomy to the canonical pentest 5-tier scale
`Critical / High / Medium / Low / Informational` plus a non-severity `### Open Questions` section,
scoped to security-review ONLY. This is the deliberate vocabulary-divergence point that reverses the
Phase 7 "unified lexicon" decision for security alone -- `lz-review` / `reviewer` KEEP the old taxonomy.

Purpose: close the long-standing doc drift between REQUIREMENTS.md (which always said security was
"Critical/High/Medium") and the shipped `Important/Suggestions` taxonomy, and adopt a recognized
security-severity ladder with a clean Low-vs-Informational adjudication rule, omit-when-empty
semantics (kills the `(none)` false-assurance bug), and a completeness caveat.

Output: an atomic lockstep edit (ONE commit) across three core surfaces -- the agent grammar
(S1), the skill render-verbatim contract (S2), the regression-gate fixture (S3) -- plus two doc
touch-ups (S4: ROADMAP goal text, context-packaging.md enum-divergence annotation), gated by the
existing `D-security-reviewer-budget.sh` self-extract/self-test retargeted to the 5-tier grammar
and a closing asymmetric scope-fence proof.

CRITICAL ATOMICITY (WR-05 few-shot-drift scar): LLMs follow worked examples over stated rules. The
header list, the skeleton, EVERY worked example, the `<output_constraints>` block, the
`<do_not_include>` items, AND the fixture's self-extract source MUST change together in ONE atomic
unit, committed ONCE -- a split commit ships a mixed-vocabulary agent and the fixture self-extract
goes RED until the agent example lands. Tasks 1-6 below are ONE plan; execute and commit them as ONE unit.
