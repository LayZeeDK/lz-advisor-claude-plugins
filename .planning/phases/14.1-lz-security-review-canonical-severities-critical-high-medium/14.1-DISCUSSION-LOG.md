## Severity rungs + Suggestions home (merged via clarification)

The rung-count and Suggestions-home questions merged after the user surfaced two points:
(1) `(none)` under a severity is misleading in a security report when the section is empty only because of the top-3-5 curation filter, not a true absence;
(2) include Low, but prioritize higher severities.

Web research (OWASP, CVSS, pentest report structure, NIST/PTES) was run at the user's explicit "ultrathink + research the web" directive.

| Option | Description | Selected |
|--------|-------------|----------|
| Canonical 5-tier: C/H/M/L + Informational | C/H/M/L = exploitable vulns; Informational = hardening/observation (no direct risk). Re-triage old Suggestions to Low or Informational. | (checked) |
| 4 rungs, collapse hardening into Low | Conflates hardening with minor vulns; drops the canonical vuln-vs-observation distinction. | |
| 4 rungs + bespoke ### Hardening Recommendations | Right intent, non-canonical label; Low-vs-Hardening adjudication ambiguity. | |

**User's choice:** Canonical 5-tier (C/H/M/L + Informational).
**Notes:** Plus omit-when-empty (no `(none)`) and priority curation, both user-driven from Points 1 + 2. Supersedes the SEED/ROADMAP 3-rung framing.
