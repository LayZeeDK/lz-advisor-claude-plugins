**The two Important findings are hard blockers (both code-grounded against the current aggregator):**

- **R1-1 (Important) -- claim `id` path-safety missing at read-time in `mergeClusters`.**
  `mergeClusters` (`lz-deep-research-aggregate.mjs:250-251`) validates that `claims[].id` is a
  non-empty string (AGG-1 from Phase 17.1) but never runs `safeId()` on it. A path-traversal claim
  `id` (e.g. `"../evil"`) is therefore accepted at read-time and only rejected LATE, in `tally()`
  at `:502` -- `safeId(String(cl.members[0].id))` -- which is called WITHOUT a `file` argument.
  That late rejection throws a `ContractError` whose `.file` is `undefined`, so the CLI's
  `(${err.file})` annotation cannot name which `claims/<worker>.json` authored the malicious id.
  This violates the AGG-5/6/7 `.file` discipline established in Phase 17.1 (and is the exact sibling
  of 17.1's WR-02, which fixed the same gap for `excerpt_id` in `quoteOutcome`). `mergeClusters`
  already stamps `_file = path.join(claimsDir, f)` on every raw claim (`:271`), so the originating
  path is available at the read boundary.

- **R2-1 (Important) -- `readJson(f).verdict` throws a raw `TypeError` on a literal-null vote file.**
  `tally()` at `:522` reads `const verdict = readJson(f).verdict`. If a vote file `votes/<id>-<s>.json`
  contains the JSON literal `null` (well-formed JSON, parses cleanly), `readJson(f)` returns `null`
  and `null.verdict` throws `TypeError: Cannot read properties of null (reading 'verdict')` -- a
  bare native Error that BYPASSES the `ContractError` discipline every other malformed-input path
  uses (`readJson` itself wraps read/parse failures in `ContractError` carrying `.file`). The seat
  read at `:522-523` already treats a present-but-null `verdict` field as `insufficient`; the defect
  is specifically the structurally-null (or non-object) RECORD reaching `.verdict` unguarded.

## Implementation Decisions

> All gray areas auto-selected and auto-resolved under `--auto`. Per `--analyze`, the trade-off
> tables behind each recommended option are in `17.2-DISCUSSION-LOG.md`. No human checkpoint was
> needed: the two Important findings are code-grounded (HIGH confidence, clear fix patterns inherited

> catches a mischaracterization). Neither sits in the high-impact / low-confidence trap quadrant.

### R1-1: where to enforce `claims[].id` path-safety

- **D-01:** Enforce path-safety at **read-time in `mergeClusters`**, not (only) late in `tally()`.
  Call `safeId(c.id, path.join(claimsDir, f))` at the same read boundary where the AGG-1 non-empty
  guard already lives (`:250`), so a path-traversal `id` is rejected with a `ContractError` carrying
  the originating worker file BEFORE it propagates through merge/rank/tally. This is the literal ask
  of R1-1 ("missing at read-time ... violating AGG-5/6/7 `.file` discipline") and the exact analog of
  17.1's WR-02 excerpt_id fix. ADDITIONALLY, thread a `file` argument into the two late `safeId`
  calls in `tally()` (`:501` clusterId, `:502` memberId) as defense-in-depth so no `safeId` call
  anywhere can throw a `.file`-less `ContractError`. (Read-time is primary; the tally annotations are
  belt-and-suspenders, since the cluster id is derived from `'cluster' + N` and the member id is now
  pre-validated.)

### R2-1: how to handle a literal-null / non-object vote record

- **D-02:** Fail **closed with a `ContractError`** when `readJson(f)` returns a non-object (null or
  primitive) vote record, annotated with the file path `f` -- NOT a lenient coercion to
  `insufficient`. Rationale: a literal-`null` vote file is malformed worker output (a structural
  violation -- there is no record), categorically distinct from a well-formed record whose `verdict`
  field is absent/null (which legitimately stays lenient -> `insufficient` at `:523`). Failing closed
  matches the project's established fail-hard posture for malformed worker data (Phase 17.1 D-01 /
  AGG-Q1) and restores the `ContractError` coverage R2-1 names as bypassed. Concretely:
  `const rec = readJson(f); if (rec == null || typeof rec !== 'object') throw new ContractError('malformed vote record (expected object): ' + JSON.stringify(rec), f); const verdict = rec.verdict;`
  The existing `verdict == null ? 'insufficient' : verdict` at `:523` is PRESERVED unchanged (the
  present-but-null-field leniency is intentional and a separate concern from R2-1).
  - **Alternative considered (not chosen):** treat a null record as `insufficient` (mirror `:523`).
    Rejected because it would silently absorb structurally-broken worker output, contradicting the
    fail-closed discipline; recorded so the planner does not re-litigate.

### Suggestion findings -- labeling hygiene and test coverage

- **D-03:** Treat the labeling-hygiene Suggestion as in scope and **reconcile it against Phase 17.1's
  deferred WR-03** (the `WR-04` label that denotes two unrelated concerns: the missing-id guard in
  the test/schema vs. the normalized-substring caveat in the source/schema). If R2-2/R1-2 is the same
  concern, the coordinated source+schema+test relabel is now appropriate -- the 17.1 deferral was
  bandwidth, not principle. CONSTRAINT: preserve ROADMAP Phase 17.1 SC-4's literal "WR-04 test exists"
  acceptance wording (keep `WR-04` as an alias/co-label on the missing-id test rather than deleting
  the token), and do not gratuitously re-touch the frozen Phase-16/17 caveat comment beyond the
  relabel. Exact disposition follows the recovered finding text (D-05).
- **D-04:** Each Important fix gets a **mutation-verified regression test** (Phase 17.1 precedent:
  the test must FAIL when the guarded behavior is removed). Specifically: (a) a path-traversal claim
  `id` aborts with `ContractError` whose `.file` names the worker (not `undefined`) -- the R1-1 guard;
  (b) a literal-`null` vote file raises `ContractError` (not a raw `TypeError`), annotated with the
  file -- the R2-1 guard. Use the inline `tmpRunDirWithWorker` helper already in the test suite (17.1
  D-03 pattern; no new committed `__fixtures__` dir). The test-coverage-gap Suggestion(s)
  (R1-3/R2-3, whichever) are recovered from the lz-review text and default to the same
  mutation-verified regression shape.

## Existing Code Insights

### Reusable Assets

- `safeId(id, file)` (`:149-158`) -- ALREADY accepts an optional `file` arg and throws
  `ContractError('unsafe id (path traversal rejected): ...', file)`. The R1-1 fix is purely to CALL
  it at read-time with the worker path; no change to `safeId` itself.
- `_file` stamping in `mergeClusters` (`:271`: `raw.push({ ...c, source: w.source, _file: path.join(claimsDir, f) })`)
  -- the originating worker path is already available at the read boundary for the R1-1 annotation.
  `_file` is internal and never leaks into `survivors.json` (the survivor record is built explicitly).
- `readJson(p)` (`:163-177`) -- the `ContractError`-wrapping read/parse pattern; the R2-1 guard
  extends the same discipline to a structurally-null parsed result.
- `tmpRunDirWithWorker` helper in the test suite -- used by WR-01/02/03/04 tests for inline run dirs;
  the two new D-04 regression tests reuse it (no new committed fixture dir, per 17.1 D-03).

### Established Patterns

- **ContractError `.file` discipline (AGG-5/6/7, WR-02):** every contract abort must carry `.file`
  so the CLI's `(${err.file})` annotation (`:653` region) names the offending worker. R1-1 closes
  the last `safeId` paths that violate this; D-01/D-02 keep new aborts consistent.
- **Fail-closed on malformed worker data (17.1 D-01 / AGG-Q1):** a path-traversal id or a
  structurally-null vote record aborts the run with a `ContractError` rather than silently skipping.
  D-02 applies this to the null vote record.
- **Mutation-verified tests (17.1 review methodology):** a regression test must demonstrably FAIL
  when its guarded behavior is deleted -- not merely pass on the fixed code (avoids the TEST-2
  tautology class of defect).
- **node:test + assert, FILE-form gate:** `node --test <the .test.mjs file>` (not the dir form,
  which false-fails on this host).

### Integration Points

- The `node --test plugins/lz-advisor/skills/lz-deep-research/scripts/lz-deep-research-aggregate.test.mjs`
  command is the acceptance gate -- must pass green with the two new regression tests added.
- Phase 18 consumes the corrected aggregator + schema as its frozen input contract; these fixes are
  read-boundary / error-shape only and MUST NOT change the tally rubric, the confidence enum, or the
  survivor-record shape Phase 18 depends on.
