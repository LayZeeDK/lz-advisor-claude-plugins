# Phase 17.2 Plan 01: lz-review finding closure (R1-1 + R2-1) Summary

Closed the two Important lz-review findings against the deterministic aggregator: R1-1 enforces claim `id` path-safety at READ-time in `mergeClusters` (annotated with the authoring worker file) plus threads `.file` into `tally`'s two late `safeId` calls as defense-in-depth; R2-1 fails closed with a `ContractError` on a structurally-null / non-object vote record before the `.verdict` read. Both fixes carry mutation-verified regression tests (R1-3/R2-3 coverage Suggestions) that assert `err.name === 'ContractError'` and `err.file`, not merely that a throw occurs. Suite 28/28 green under the FILE-form gate; the `:523` present-but-null-field leniency and all frozen contracts (confidence enum, tally rubric branch order, survivor-record shape) are unchanged.

## What Was Built

### Task 1 -- R1-1 read-time claim id path-safety guard (commit `6f6d9ec`)
- Added `safeId(c.id, path.join(claimsDir, f));` in `mergeClusters` immediately after the AGG-1 non-empty guard and before the text guard. The return value is discarded -- the call is a validating side-effect at the read boundary; `safeId` throws `ContractError('unsafe id (path traversal rejected): ...', file)` on `..`/separators/`.`.
- The AGG-1 `'claim missing non-empty id'` guard is KEPT intact (distinct message; the WR-04 test asserts `/missing non-empty id/`, which `safeId`'s `'invalid id (expected non-empty string)'` would break). Both guards coexist.
- Added the R1-1 regression test (after TEST-9): a `'../evil'` claim id on an otherwise-valid claim with NO excerpts dir. The test asserts `caught.name === 'ContractError'`, `typeof caught.file === 'string'`, and `caught.file.endsWith('w1.json')`.
- Discriminator (RESEARCH Pitfall 4 option a): with no excerpts the claim would DROP at quote-recheck before reaching `tally` if the read-time guard were absent -- so the `err.file`-ending-in-`w1.json` assertion is what fails when the guard is removed.

### Task 2 -- R2-1 non-object vote-record guard (commit `8f61f57`)
- Replaced `const verdict = readJson(f).verdict;` in `tally` with `const rec = readJson(f);` + `if (rec == null || typeof rec !== 'object') { throw new ContractError('malformed vote record (expected object): ' + JSON.stringify(rec), f); }` + `const verdict = rec.verdict;`.
- The `:523` line `seats.push(verdict == null ? 'insufficient' : verdict);` is PRESERVED byte-for-byte -- the present-but-null-FIELD leniency is a separate, frozen concern from the structural-RECORD guard.
- No `Array.isArray` rejection added (an array is `typeof 'object'` and reads `.verdict` as `undefined` -> the lenient path; rejecting it is scope creep beyond D-02).
- Added the R2-1 regression test (end of file): a surviving single claim (matching excerpt) with `votes/cluster0-0.json` containing literal `null`. Asserts `err.name === 'ContractError'` (rejecting a `TypeError`), `/malformed vote record/`, and `caught.file.endsWith('cluster0-0.json')`.

### Task 3 -- R1-1 defense-in-depth .file on tally safeId calls (commit `da4355a`)
- Computed `const memberFile = cl.members && cl.members[0] ? cl.members[0]._file : undefined;` after `votesDir`, and threaded it into both `safeId(cl.id, memberFile)` and `safeId(String(cl.members[0].id), memberFile)`.
- Belt-and-suspenders (D-01): neither is a live attack path (cluster id is `'cluster' + N`; member id is now read-time-validated by Task 1) -- the annotation exists so no `safeId` call anywhere can throw a `.file`-less `ContractError`. `_file` survives `recheckClusters` (`:419` `{ ...m }`, `:429` `{ ...cl, members: survivingMembers }`).
- Rubric branch order, seat-lookup loop, and all other `tally` logic untouched (single hunk at the top of `tally`).
