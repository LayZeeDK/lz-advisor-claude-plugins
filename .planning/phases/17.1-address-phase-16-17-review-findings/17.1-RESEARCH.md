### Pattern 5: TEST-2 inline file-order stability test (D-03 approach)

```javascript
test('SC-1 listJson sort is stable across OS-dependent readdirSync order', () => {
  // Create two claim files where alphabetical order != creation order.
  // z-worker.json is created first; a-worker.json is created second.
  // After sort(), a-worker.json is processed first -> cluster0 maps to claim A.
  const runDir = fs.mkdtempSync(path.join(os.tmpdir(), 'lz-dr-sort-'));
  try {
    const claimsDir = path.join(runDir, 'claims');
    const excerptsDir = path.join(runDir, 'excerpts');
    fs.mkdirSync(claimsDir, { recursive: true });
    fs.mkdirSync(excerptsDir, { recursive: true });
    // Write z-worker first (would be processed first if no sort), then a-worker.
    fs.writeFileSync(
      path.join(claimsDir, 'z-worker.json'),
      JSON.stringify({ worker: 'zw', source: 'sz',
        claims: [{ id: 'cz', text: 'Z claim distinct text', quote: 'Z claim', excerpt_id: 'ez' }] }),
      'utf8',
    );
    fs.writeFileSync(
      path.join(claimsDir, 'a-worker.json'),
      JSON.stringify({ worker: 'aw', source: 'sa',
        claims: [{ id: 'ca', text: 'A claim distinct text', quote: 'A claim', excerpt_id: 'ea' }] }),
      'utf8',
    );
    fs.writeFileSync(path.join(excerptsDir, 'ez.txt'), 'Z claim distinct text', 'utf8');
    fs.writeFileSync(path.join(excerptsDir, 'ea.txt'), 'A claim distinct text', 'utf8');
    const r = aggregate(runDir);
    // After sort, a-worker.json comes first; its claim should be cluster0 (first ranked by corroboration=1, then lex tiebreak).
    // The stable property is: regardless of OS readdirSync order, the result is byte-identical.
    const a = aggregate(runDir);
    const b = aggregate(runDir);
    assert.deepEqual(a.survivors.map(s => s.claim), b.survivors.map(s => s.claim));
    // And specifically: the claim from a-worker (alphabetically first) should come first after sort+rank tiebreak.
    // (Both have corroboration=1; lex tiebreak on normalize(text) -- 'a claim' < 'z claim'.)
    assert.equal(r.survivors[0].claim, 'A claim distinct text');
  } finally {
    fs.rmSync(runDir, { recursive: true, force: true });
  }
});
```

Note: The planner may simplify this test. The core requirement from D-03 is: write files with
names where alphabetical order != creation order, assert `survivors[0].claim` is the alphabetically-
first worker file's claim, not the creation-order-first. The `deepEqual` is secondary (the
existing SC-1 at line 330 already covers in-process determinism); this test covers the sort axis.

### Anti-Patterns to Avoid

- **Modifying the `tmpRunDirWithWorker` helper to auto-cleanup:** The helper returns the path
  and its callers call `aggregate(runDir)` after. Auto-cleanup inside the helper would destroy
  the dir before the caller uses it. Wrap the CALLER sites in `try/finally`, not the helper.

- **Putting WR-04 test before AGG-1 fix:** The test for a missing `id` must be authored AFTER
  the guard exists; otherwise the test will fail on assertion (the guard does not fire yet). Plan
  ordering must be: Plan A committed -> then Plan B.

- **Combining SCHEMA-1 interim and post-AGG-1 promotion into separate commit passes:** These
  two edits to the same row should land in a single commit so the schema is never in a state where
  the interim caveat is present alongside already-fixed code. Per CONTEXT.md, Plan C can go after
  Plan A (which fixes AGG-1) so both stages of SCHEMA-1 can be done in one edit.

- **Forgetting the `safeId` `.file` argument fix (AGG-6):** The safeId call at source line 283
  is `safeId(f.slice(0, -'.txt'.length))` with no second arg. Fix must add
  `path.join(excerptsDir, f)` as the second arg so the `ContractError` gets its `.file` property.

- **Using dir-form node:test gate:** `node --test <dir>` spuriously exits 1 on this host (Node
  v24 / Windows arm64). The gate command is FILE-form only:
  `node --test plugins/lz-advisor/skills/lz-deep-research/scripts/lz-deep-research-aggregate.test.mjs`

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Per-test tmpdir cleanup | A shared cleanup registry or test lifecycle hook | `try/finally { fs.rmSync(runDir, ...) }` inline in each test | node:test has no built-in `afterEach`; the inline try/finally is the established pattern; each test already creates its own dir |
| Multiple readdirSync wrappers | A new `safeReaddirSync` utility function | Inline try/catch at each call site | Only two call sites; a utility abstraction adds indirection for no reuse gain; consistent with how `readText` is a one-liner and `readJson` wraps it inline |
| New fixture directory for TEST-2 | A committed `__fixtures__/file-order-test/` dir | Inline `tmpRunDir` per D-03 | D-03 explicitly prohibits a new committed `__fixtures__` dir for this test |

## Common Pitfalls

### Pitfall 1: AGG-1 fix location -- insert AFTER quote guard, BEFORE raw.push

**What goes wrong:** Inserting the `c.id` guard before the `c.text`/`c.quote` guards changes
the WR numbering and could confuse future readers about the validation order.
**Why it happens:** The natural insertion point "add id guard after quote guard" is lines 230-232.
**How to avoid:** The guard block reads WR-01 (text), WR-02 (quote) -- insert WR-04 (id) as the
third guard AFTER the quote guard and BEFORE `raw.push()` at line 234. Source lines 226-234 are
the exact insertion window.
**Warning signs:** If the guard is before line 226, it's in the wrong position.

### Pitfall 2: SCHEMA-1 two-stage edit order

**What goes wrong:** Editing SCHEMA-1 to `yes (fail-closed)` without the interim caveat, then
the editor's context is stale and the caveat is forgotten.
**Why it happens:** Two-stage edits to the same cell are easy to collapse into one.
**How to avoid:** Since Plan A (which fixes AGG-1 in the code) and Plan C (which fixes the schema)
run in the correct order (Plan A first), Plan C can do BOTH stages of SCHEMA-1 in a single edit:
go directly from `yes` to `yes (fail-closed)` with the WR-04 reference, bypassing the interim
state entirely. The interim caveat was needed only if schema edits happened BEFORE AGG-1 was coded.
**Warning signs:** If Plan C runs before Plan A, the interim caveat is required.

### Pitfall 3: TEST-5 cleanup wrapping the wrong level

**What goes wrong:** Wrapping inside `tmpRunDirWithWorker` (the helper) instead of at the test
call sites.
**Why it happens:** The cleanup logic looks like it belongs in the function that creates the dir.
**How to avoid:** `tmpRunDirWithWorker` returns the path to the caller; the caller then calls
`aggregate(runDir)`. The dir must still exist when `aggregate` runs. Cleanup must be AFTER the
`assert`, in the calling test's `finally` block. The helper at line 220 should NOT be modified
to auto-cleanup (it would destroy the dir before use).
**Warning signs:** Tests for WR-01/02/03 currently do NOT have cleanup and those tests use
`tmpRunDirWithWorker`. The TEST-5 finding asks to fix the cleanup for the THREE inline
`mkdtempSync` sites (lines 145, 220, 297 in the original file numbering) -- these are tests that
call `mkdtempSync` DIRECTLY (not via the helper). The `tmpRunDirWithWorker` helper itself IS
one of those direct calls (line 220 of the helper definition), but the finding is about the
tests that call the helper -- each such call site should have cleanup.

Note: After re-reading, the TEST-5 finding says "three `mkdtempSync` sites" at lines 145, 220,
297. Line 145 is inside the `PIPE-07 / D-02 stdout` test (a direct `mkdtempSync`). Line 220 is
inside `tmpRunDirWithWorker` (the helper itself). Line 297 is inside `SC-2 CRLF+BOM` test. The
correct interpretation: line 145 and line 297 tests get `try/finally`. For line 220 (the helper),
the helper creates dirs for WR-01/02/03 callers; those callers should also get cleanup. The
planner should add `try/finally` wrappers to ALL test call sites that create temp dirs.

### Pitfall 4: TEST-2 sort stability test writes too many claims

**What goes wrong:** Using mergeable claims (high Jaccard) in the two worker files, causing them
to merge into one cluster -- making the test vacuous (only one survivor, so order is undetectable).
**Why it happens:** Default test templates tend to reuse the same claim text.
**How to avoid:** The two worker files MUST have DISTINCT, non-mergeable claims (disjoint token
sets, Jaccard < 0.6). The test asserts on `survivors[0].claim` being the alphabetically-first
file's claim, which requires them to be distinct survivors.

### Pitfall 5: AGG-Q1 comment placement

**What goes wrong:** Adding the fail-hard posture comment at the `safeId` function instead of at
the `quoteOutcome` call site.
**Why it happens:** The path-traversal check lives in `safeId`.
**How to avoid:** The comment must go at `quoteOutcome` line 311 (`const citedId = ...`), because
that is where the design DECISION is made (fail-hard vs fail-soft for a malformed `excerpt_id`).
The `safeId` function is a utility; the policy comment belongs at the decision point.
