# Phase 17.1 Plan 02: Deep-research aggregator test-suite findings Summary

Turned the two tautological Important test gaps (TEST-1 SYNTH_CAP, TEST-2 cross-file-order) into real regression guards, added the WR-04 missing-id test that Plan 17.1-01's AGG-1 guard makes passable, and closed the six Suggestion-grade coverage/cleanup additions (TEST-4..9) on `lz-deep-research-aggregate.test.mjs`. Suite is green at 25 tests, exit 0.

## What was built

### Task 1 (commit cdac1c3): TEST-1, TEST-2, TEST-3

- **TEST-1 (SYNTH_CAP):** Added `assert.match(r.summary, /synth \d+->20/)`, `assert.equal(r.survivors.length, 20)`, and `assert.equal(CEILINGS.SYNTH_CAP, 20)` to the existing SC5-5 test. The `ceilings-enforced` fixture's 31 claims trip MAX_VERIFY_CLAIMS (31->24) AND SYNTH_CAP (24->20). Removing the SYNTH_CAP drop logic now FAILS the suite (the synth marker vanishes and survivors.length becomes 24).
- **TEST-2 (cross-file-order determinism):** New inline-tmpRunDir test (D-03). Writes `z-worker.json` first, `a-worker.json` second (creation order is the reverse of alphabetical). Two disjoint claims (jaccard < 0.6, corroboration 1 each) so rankClusters' normalized-text lexical tiebreak decides order. `a-worker`'s claim normalizes to "alpha beats beta always" which sorts before `z-worker`'s "zeta tops omega daily", so `survivors[0].claim` must be the alphabetically-first worker claim regardless of disk read order. Strengthened with a byte-identical second-run deepEqual cross-check. The primary load-bearing property: read order does not change the output (only stable because listJson sorts the directory listing).
- **TEST-3 (WR-04):** New test asserting `assert.throws(() => aggregate(runDir), /missing non-empty id/)` on an id-less claim. Passes only because Plan 17.1-01 added the AGG-1 `claim missing non-empty id` guard.

### Task 2 (commit 78531f7): TEST-4, TEST-5, TEST-6, TEST-7, TEST-8, TEST-9

- **TEST-4 (fallback confidence lock):** SC5-2 now asserts `survivors.length === 1`, `quote_fidelity === 'downgraded'`, and `confidence === 'High'`. The `wrong-passage-downgraded` fixture's vote files are member-id-named (`c1-0/1/2.json`, all unrefuted), so the member-id vote-file fallback must fire and yield High; a silent fallback failure (Unsupported) is now caught.
- **TEST-6 (malformed JSON):** New test writing raw `not json` bytes into a claims file; asserts `/malformed JSON/`.
- **TEST-7 (missing claims[] array):** New test with `tmpRunDirWithWorker({ worker: 'w1', source: 's1' })`; asserts `/missing claims\[\] array/`.
- **TEST-8 (votes_ignored):** New inline-run-dir test with one surviving claim plus four cluster0 vote seats (0..3). The 4th seat (beyond VOTES_PER_CLAIM=3) is counted into `caps.votes_ignored`; asserts the summary contains `votes_ignored 1`. Exercises the EXISTING extra-seat count path only (AGG-2 non-contiguous-gap behavior deferred to Phase 18 per D-02).
- **TEST-9 (path-traversal):** New test with `excerpt_id: '../evil'` plus a matching excerpt; asserts `/path traversal rejected/` (fail-hard posture D-01).
- **TEST-5 (temp-dir cleanup):** Wrapped all three original `mkdtempSync` sites (PIPE-07/D-02 5-label, the `tmpRunDirWithWorker` callers, SC-2 CRLF+BOM) plus every new temp-dir test in `try/finally { fs.rmSync(runDir, { recursive: true, force: true }) }`. Cleanup is in each caller, not inside the shared helper (which returns before the caller is done). `rmSync` now appears 11 times (gate: >= 5).
