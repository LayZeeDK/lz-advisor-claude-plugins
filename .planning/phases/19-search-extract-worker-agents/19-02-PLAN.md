<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker -> run dir | The worker writes content-derived filenames (excerpt_id, source filename). |
| fetched source text -> main session | Raw fetched content must stay on disk, never enter the parent context. |
| worker tool grant -> environment | An over-broad `tools` grant would let a worker act beyond its bounded role. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-05 | Elevation of Privilege | worker `tools` frontmatter | mitigate | Least-privilege grants (search=[WebSearch,Write], extract=[WebFetch,Write]); no Read/Bash (V4). Verified by the frontmatter `git grep` structural + over-privilege-negation assertions in Tasks 1-2. |
| T-19-06 | Information Disclosure | receipt / excerpt | mitigate | The one-line receipt carries counts only; raw source text stays in excerpts/<id>.txt on disk; the main session never holds it (D-14, AGG-03). Verified by the receipt-format assertion (Task 3). |
| T-19-07 | Tampering | worker-authored source filename | mitigate | The SHA-256-hex filename (D-13) has no path separators; the aggregator's read-time safeId rejects any unsafe content-derived id (V12). The round-trip fixture uses the real sourceFilename hex. |
| T-19-08 | Spoofing | claims[].source vs sources/<id>.json id | mitigate | The schema requires the canonical key be IDENTICAL across claims[].source and the source-record `id` (D-08); the fixture asserts equality so a mismatched source can't under-count corroboration (V5). |
| T-19-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; agents are Markdown. No legitimacy checkpoint required (RESEARCH Package Legitimacy Audit). |
</threat_model>
