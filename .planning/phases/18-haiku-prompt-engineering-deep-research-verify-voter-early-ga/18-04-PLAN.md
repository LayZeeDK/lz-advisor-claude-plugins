## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-04-S | Spoofing / Tampering | prompt-injection in claim/evidence/KS text steering the voter verdict | mitigate | The voter prompt frames fetched text as DATA to be skeptically verified, not instructions; the adversarial role + disconfirming search bias toward `refuted` (the safe direction). The deterministic gate scores verdict-vs-gold-label, so an injected "say unrefuted" that succeeds shows up as a false-uphold the gate counts -- injection cannot silently pass the gate. |
| T-18-04-E | Elevation of Privilege | over-broad voter tool grant | mitigate | Least-privilege tools per arm: `["WebSearch","WebFetch","Write"]` open-book, `["Write"]` closed-book control; no Read/Glob/Bash. The Write grant is the minimum needed to emit the vote file. |
| T-18-04-I | Information Disclosure | open-book voter retrieving the leaked published verdict (eval-integrity, not classic STRIDE) | mitigate | Restrict open-book retrieval to the AVeriTeC revised KS (2024-11-15) + per-claim date cutoff; forbid live web search and fact-check-domain reliance (D-05). |
| T-18-04-T | Tampering | lock-rule numbers drifting from the aggregator constants | mitigate | The lock-rule doc copies `EVAL_CONSTANTS` (anti-drift house style); the key_link binds them; Plan 18-05 enforces via `lockRuleCheck`. |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs (doc + agent files only). No legitimacy checkpoint required. |
</threat_model>
