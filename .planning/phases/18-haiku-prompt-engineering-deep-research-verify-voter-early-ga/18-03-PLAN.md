## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HuggingFace CDN -> loader | Downloaded JSONL/KS text is UNTRUSTED input crossing into the loader (prompt-injection inside claim/evidence text flows downstream to voters; tampered files; oversized payloads). |
| HF token -> loader | The HF secret bearer token is resolved at fetch time from the env (HF_TOKEN) OR the huggingface_hub credential file (`${HF_HOME or ~/.cache/huggingface}/token`). |
| loader -> cache filesystem | Content-derived basenames written into the cache dir. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03-T1 | Tampering | swapped/tampered dataset file (supply-chain) | mitigate | Pin the HF revision sha in the manifest + fetch `resolve/<sha>/...` + locally-computed sha256 fail-closed (`ContractError(/checksum mismatch/)`); the test asserts the mismatch throws. |
| T-18-03-I1 | Information Disclosure | HF token leak in logs/commits/cache | mitigate | Resolve the token (env HF_TOKEN or the `${HF_HOME or ~/.cache/huggingface}/token` credential file) into memory at fetch time only; use it solely as the `Authorization: Bearer` header; never echo it, never write it to the manifest or cache; `.gitignore` the cache; the loud-fail messages name the token requirement without printing the value. The credential file is read, never written or committed. |
| T-18-03-T2 | Tampering | path traversal via a crafted example uid / cache filename | mitigate | `safeId` (basename-only; rejects separators, `..`, `.`, Windows reserved device names) on every content-derived basename before `path.join` into the cache dir. |
| T-18-03-D | Denial of Service | malformed/oversized downloaded JSON crashes or hangs the loader | mitigate | Fail-closed `readJson`/`ContractError` parse (never bare JSON.parse); explicit 401-detection-then-exit (no infinite retry, Pitfall 1); reject oversized inputs (the aggregator-ceilings precedent). |
| T-18-03-PI | Tampering (downstream) | prompt-injection text inside fetched claim/evidence reaching the voter | mitigate (here, partial) | The loader is the integrity boundary (sha256 + license-compliant manifest); the voter agents (Plan 18-04) treat fetched text as data, not instructions. | T-18-03-LIC | (license / compliance) | redistributing CC-BY-ND / CC-BY-NC text | mitigate | Vendor ONLY WiCE (ODC-BY/MIT) with NOTICE; commit only the derived manifest for ND/NC/gated sources; fetch their text into the gitignored cache; never commit it. |
| T-18-SC | Tampering | npm/pip/cargo installs | mitigate | Zero package installs (zero-dep contract enforced by the copied SC-2 test). No legitimacy checkpoint required. |
