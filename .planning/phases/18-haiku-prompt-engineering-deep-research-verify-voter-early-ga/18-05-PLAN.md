<objective>
Run the pre-registered gating eval and settle the Haiku-first flag (or raise the decision to the
user). Confirm the lock rule (Plan 18-04) is committed first, run the `--validate` oracle pre-flight
(trusted Sonnet ~100% on a known-answer seed), stage the SUBTLE stratum FIRST (the sole hard gate)
with k>=5 temp-0 isolated voter calls per (claim x seat x tier) via the headless `claude -p` path,
collect votes, and feed the counts to the deterministic aggregator + `lockRuleCheck`. On PASS,
escalate the SUBTLE subset to reliable=15 before declaring PASS and record the intent to flip the
Haiku-first flag ON; on FAIL either gate, RAISE THE DECISION TO THE USER (EVAL-03) -- Sonnet-default
ships in the interim regardless. Abort-early ONLY on FAIL. Stage across credit-reset windows.

NOTE: the Haiku-first flag's concrete OFF home is `EVAL_CONSTANTS.HAIKU_FIRST_DEFAULT=false`
(Plan 18-02). This plan SETTLES the flag's value (PASS = flip-ON intent; FAIL = stays OFF + raise),
but the SKILL-SIDE WIRING of the flag into the lz-deep-research skill is deferred to Phase 20; the
result artifact records the flag location + value so Phase 20 can trace it (COST-02).

Purpose: EVAL-03 -- the staged eval run produces the PASS/FAIL verdict that settles the voter default
for Phases 19-20, or raises the non-viable decision to the user. This is the empirical payoff of the
whole phase.
Output: the run driver `lz-eval-run.mjs` + the committed `18-EVAL-RESULT.md` verdict artifact.

NOTE: this plan involves live model calls, network, the gated-dataset HF_TOKEN, and the shared
5-hour usage pool. It is NOT autonomous: the FAIL path raises to the user, and a missing HF_TOKEN
bounds the run to the WiCE-only closed-book SUBTLE gate.
