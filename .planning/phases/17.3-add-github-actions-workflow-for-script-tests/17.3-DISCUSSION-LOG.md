## Coverage tooling

| Option | Description | Selected |
|--------|-------------|----------|
| Built-in `node --test --experimental-test-coverage` | Zero deps; line/branch/function + threshold flags; matches the stdlib-only aggregator | [x] |
| c8 / istanbul / nyc | Richer HTML reports, some condition detail | |
| vitest coverage | Full framework + coverage, but a test-runner migration | |

**Choice:** Built-in node coverage (recommended).
**Notes:** The aggregator is deliberately Node-stdlib-only and the repo has no root `package.json`.
A coverage dependency would break the zero-dependency ethos for marginal value. HIGH confidence,
reversible. (CONTEXT D-01.)

---

## Coverage dimensions and thresholds

| Option | Description | Selected |
|--------|-------------|----------|
| line + branch + function, fail-closed, target 100% library surface | The dimensions built-in coverage supports; gate fails the job below threshold; `node:coverage` pragmas for the unreachable CLI bootstrap | [x] |
| line only | Simplest, but weak signal | |
| Lower global threshold to absorb dead bootstrap lines | Avoids pragmas, but dilutes the gate | |

**Choice:** Enforce all three supported dimensions, fail-closed, target 100% on the library surface
(recommended).
**Notes:** 42-test/951-LOC suite over 739-LOC source makes a high gate realistic. Exact enforced
numbers set after a measurement run on the pinned Node; prefer `// node:coverage disable/ignore`
pragmas over lowering the global gate. (CONTEXT D-02, D-03.)

## Test discovery form

| Option | Description | Selected |
|--------|-------------|----------|
| Glob `plugins/lz-advisor/skills/**/*.test.mjs` | Auto-picks up future test files; explicit and robust on CI | [x] |
| Explicit single file path | Matches the dev-host gate but must be edited per new test | |
| Bare directory argument | Triggers the host-specific spurious-exit-1 quirk | |

**Choice:** Glob over the bundled plugin script tests (recommended).
**Notes:** The bare-dir `node --test <dir>` exit-1 quirk is Windows-arm64-host-specific; CI runs on
ubuntu where discovery works, but the explicit glob is the intention-revealing, future-proof form.
(CONTEXT D-05.)

## Node version pin

| Option | Description | Selected |
|--------|-------------|----------|
| `.node-version` = `lts/<codename>`, single version, research-confirmed | Roadmap-locked format; `setup-node` `node-version-file` consumes it; fnm-compatible locally | [x] |
| Multi-Node matrix | More coverage of Node lines, but cost/noise for stdlib-only scripts | |
| Hardcoded numeric version | Loses the LTS-tracking intent the roadmap specified | |

**Choice:** Single pinned `lts/<codename>`, exact codename research-confirmed (candidate
`lts/krypton` = Node 24 Active LTS; fallback `lts/jod` = Node 22) (recommended).
**Notes:** Format locked by the roadmap. Single version, not a matrix. Must be recent enough for the
built-in coverage threshold flags (Node 22+). (CONTEXT D-06.)

## Triggers, concurrency, and permissions

| Option | Description | Selected |
|--------|-------------|----------|
| `pull_request` + `push: main`; concurrency group by workflow+ref, cancel-in-progress; `permissions: contents: read` | Covers every push/PR without double-runs; roadmap-locked concurrency + least-privilege | [x] |
| `push` to all branches + `pull_request` | Double-runs on PR branches | |
| Broader permissions (checks/PR write) | Unnecessary for a test-only job | |

**Choice:** PRs + push-to-main, roadmap-locked concurrency, minimal `contents: read` (recommended).
**Notes:** Concurrency and permissions are FIXED by the roadmap scope; trigger split avoids the
push+PR double-run. (CONTEXT D-07, D-08, D-09, D-10.)
