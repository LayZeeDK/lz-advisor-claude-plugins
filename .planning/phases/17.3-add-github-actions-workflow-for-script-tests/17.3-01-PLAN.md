CRITICAL -- PEEL ANNOTATED TAGS BEFORE PINNING. GitHub's "pin to a full-length commit SHA"
guidance means the COMMIT a tag resolves to, NOT the tag object. A `git ls-remote --tags` listing
shows TWO kinds of refs:
- `refs/tags/vX.Y.Z`     -> for an ANNOTATED tag this is the tag-OBJECT hash (do NOT pin this).
- `refs/tags/vX.Y.Z^{}`  -> the PEELED COMMIT the annotated tag points at (PIN THIS).
A LIGHTWEIGHT tag has only the bare `refs/tags/vX.Y.Z` line (no `^{}` line); for a lightweight tag
the bare ref already IS the commit, so pin it directly. Resolve the peeled commit via the `^{}`
line of `git ls-remote --tags` (equivalently `git rev-list -n1 <tag>`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
