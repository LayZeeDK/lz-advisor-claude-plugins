## Intent

The cross-skill provenance marker renders as **"Verdict scope: scope:
api-correctness"** -- the word "scope" appears twice (bold human label
`**Verdict scope:**` + the machine token `scope: <value>`). Rename the
human-facing label to kill the word-on-word repeat. Cosmetic / output-contract
polish; NOT an invocation-surface break (distinct from 14.1).

## Hard constraint

The machine-readable token **`scope: <value>` stays unchanged.** Downstream
skills extract the verdict's axis by greppping for `scope:\s*(\S+)` anywhere in
the output (the provenance marker self-describes so the parser does not have to
anchor on the bold label). Only the human label `**Verdict scope:**` changes.
Parser logic is therefore UNTOUCHED.

## What the marker is (background)

"Scope-Disambiguated Provenance Marker" -- defined in
`references/context-packaging.md` (the "Scope-Disambiguated Provenance Markers"
section, ~lines 356-369). Lets a downstream skill check `scope:` match before
treating an upstream verdict as authoritative outside its axis (closes "Finding
C hop 8b": a `scope: security-threats` verdict must not vouch for API
correctness). Enum values: `api-correctness` / `security-threats` /
`performance` / `accessibility`.

## Candidate labels (open decision for discuss)

| Label | Renders as | Note |
|-------|-----------|------|
| `**Verdict axis:**` | `Verdict axis: scope: api-correctness` | Reuses the spec's own word -- `context-packaging.md:367` says "re-verify on the relevant **axis**"; `lz-execute/SKILL.md:290` says "the **axis** of correctness". Smallest diff from current. **LEAN.** |
| `**Verification axis:**` | `Verification axis: scope: api-correctness` | Matches `lz-execute` prose verbatim. |
| `**Authoritative for:**` | `Authoritative for: scope: api-correctness` | Names the exact semantic (the scope-match gate). Strong runner-up. |
| `**Verdict domain:**` | `Verdict domain: scope: api-correctness` | "domain" = area of authority; neutral. |
| `**Verdict covers:**` | `Verdict covers: scope: api-correctness` | Verb-phrase; slightly informal. |
| `**Verdict lens:**` | `Verdict lens: scope: api-correctness` | Reuses "lens" vocab (OWASP Top 10 Lens / security lens), but "lens" reads security-flavored. |

**Recommendation:** `**Verdict axis:**` -- one-word swap, kills the repeat, and
uses the word the spec already uses (no new term). Runner-up: `**Authoritative
for:**` if the label should state the purpose rather than the thing.
