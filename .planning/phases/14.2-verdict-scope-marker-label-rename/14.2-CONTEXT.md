<decisions>
## Implementation Decisions

### Replacement Label

- **D-01:** The new human label is `**Verdict axis:**` -- renders `Verdict axis: scope: api-correctness`. Chosen over `Authoritative for:` / `Verdict domain:` because "axis" is ALREADY the word the codebase uses next to the marker: `lz-execute/SKILL.md:290` reads "stating the axis of correctness the verification covers" and `context-packaging.md:367` reads "re-verify on the relevant axis". The swap introduces NO new vocabulary, is a one-word change, and incidentally fixes an existing label/prose mismatch (lz-execute:290 currently labels the line `**Verdict scope:**` while its own prose already calls it "the axis"). Kills the literal word-on-word repeat.

### Rename Boundary

- **D-02:** Label-consistent boundary. CHANGE both (a) the bold output-template label `**Verdict scope:**` -> `**Verdict axis:**` on all 5 surfaces, AND (b) the documentation subsection headers / prose that name the label -- `### Verdict scope marker` -> `### Verdict axis marker` (lz-review/SKILL.md, lz-security-review/SKILL.md) and any "the Verdict scope line/marker" descriptive phrasing -> "Verdict axis". KEEP UNCHANGED: the machine token `scope: <value>`, the enum values (`scope: api-correctness` / `security-threats` / `performance` / `accessibility`), the `### Scope tag values` section, the "Scope-Disambiguated Provenance Marker(s)" feature/concept name, the `### Downstream consumer rule` "scope: match" prose, and the extraction logic -- ALL of these describe the unchanged TOKEN. Net result: a clean vocabulary split -- "scope" = the machine-token vocabulary (frozen), "axis" = the human-label vocabulary.

### Version / Release Coupling

- **D-03:** NO version or release work in this phase. Phase 15 owns the atomic 5-surface 1.0.1 -> 2.0.0 bump (the D-09 phase boundary, matching Phases 14 and 14.1 which were content-only). The label rename rides into v2.0.0. Cross-phase note for the Phase 15 planner: the `[2.0.0]` CHANGELOG entry SHOULD mention this label change (`Verdict scope:` -> `Verdict axis:`) alongside the skill-rename and security-severity-migration entries. The change is non-breaking (cosmetic output-contract polish; the token + parser are intact) but ships under the already-breaking v2.0.0.

### Atomicity & Scope Fence

- **D-04:** One atomic lockstep edit across all 5 surfaces (the `context-packaging.md` template + the 4 SKILL.md files), following the Phase 14.1 few-shot-drift discipline (WR-05): the label is a few-shot-modeled output token, so every occurrence flips together or rendered output goes mixed. Closing `git grep` gate: zero `\*\*Verdict scope:\*\*` and zero `Verdict scope marker` under `plugins/lz-advisor/`, while every `scope: <value>` token occurrence stays present and `references/context-packaging.md` extraction prose is byte-unchanged. This is a tiny diff versus 14.1, but the same discipline applies because the gate must prove the token survived and the label is fully migrated.

### Claude's Discretion

- GA-1 (label choice) was the only genuinely open call; resolved to `**Verdict axis:**` directly per the SEED lean + the adjacency evidence above (no advisor consult -- the plugin's own discipline reserves consults for high-leverage architectural moments, and a one-word cosmetic label is not one). The GA-2 rename boundary and the D-04 atomicity/gate discipline were locked at Claude's discretion within the SEED's stated intent ("Rename the label in ALL of these in one unit (token `scope: <value>` stays)").
