## What the status line carries, and why the branch letter travels on it

The single machine-readable line above is one of exactly three literals -- `GRADED`,
`NOT-RUN branch (b)`, `NOT-RUN branch (c)` -- and exactly one such line exists in this whole document.
A bare `NOT-RUN` is not admissible. The two not-run branches make materially different claims:

- **branch (b) NOT-ESTABLISHABLE-BY-METHOD** asserts something about the world -- a pre-registered
  method WAS attempted and its result is unreachable for a reason identifiable independently of the

error this phase exists to avoid. The letter therefore rides the status line so the milestone audit can
tell them apart without interpreting prose. This record legitimately discusses the grading it did not
perform and the branch it did not take, so a check counting keyword mentions would fail on a correct
document; the status line is what the structural check reads.
